I. Introduction

The rapid ongoing evolution of artificial intelligence (AI) demands explainability at the levels of data, algorithms, models, systems, and predictions, as a prerequisite for Explainable and Trustworthy AI [1, 2]. Whereas black-box classifiers can generate accurate but poorly explainable predictions, a fuzzy rule-based classification system (FRBCS) can produce not only accurate but also human-friendly and interpretable predictions [3, 4].

The nature of explanation has long been studied in social sciences. It turns out that explanations are desired to be contrastive (i.e., they are expected to explain why alternative outputs were not predicted), selected (i.e., they point only to a limited number of the most relevant causes of the phenomenon being explained), and social (i.e., they are produced as a result of interaction between the explainer and explainee) [5].

The three properties can be achieved when generating the so-called counterfactual explanations. In addition to factual explanations that aim to justify the actual prediction, counterfactual explanations rationalize why alternative predictions were not made. Conventionally, counterfactual explanations are designed to describe a set of minimal changes with respect to the given test instance's characteristics so that the algorithm's prediction would change to the desired alternative [6]. Counterfactual explanations are contrastive, as they oppose different predictions. They can be selected if, e.g., they are limited to always including fewer features than the cardinality of the set of features that the dataset contains. Finally, counterfactual explanations can be made social if explicit user preferences are used to fine-tune the originally generated automated explanations.

On one hand, a prediction of an FRBCS can be explained factually (e.g., answering the why-question "Why is the test instance predicted to be of class P?") by listing the feature-value pairs that appear in the antecedent of the rule that has the highest activation degree. On the other hand, the given prediction can be explained counterfactually (e.g., answering the why-not-question "Why is the test instance not predicted to be of class Q?"). Such so-called counterfactual explanations presuppose minimal changes in the test instance feature values for the prediction to change, making it maximally relevant to the test instance under consideration [6].

One of the major limitations of static responses to the aforementioned questions is a lack of interaction with the explainee. Instead, it is desired that the end user can customize the given explanation to further increase its utility. To do so, we devised a method for generating explanations, which incorporates user preferences to produce tailored explanations, allowing for acceptable ranges within the feature space where feasible counterfactuals can be located. As the method generates valid counterfactuals that are minimally different from the test instance, it allows the end user to draw difference between linguistic explanations for fuzzy classifiers and those for other supervised machine learning-based classifiers.

In this immersive article, the readers will be presented with a practical, step-by-step guide on how to (1) build interpretable FRBCSs, (2) add a linguistic layer on top of approximate fuzzy classifiers (i.e., those with local semantics), (3) generate factual and counterfactual explanations for the resulting systems, and (4) yield user-preferred counterfactuals. The rest of the article is structured as follows. Section II introduces the use case that we consider exemplifying the challenges and the solutions proposed. Section III illustrates basic notions of fuzzy logic, introduces a method for linguistic approximation of non-semantically grounded fuzzy linguistic terms, outlines technicalities of the specific FRBCS whose output is aimed to be explained, and presents an approach to fuzzy logic-based factual and counterfactual explanation generation. In addition, we describe how user preferences can be handled to generate single-point counterfactual explanations and briefly describe how user preferences can be tackled in these settings. Finally, Section IV discusses the results and concludes the paper.

III. Explainable fuzzy systems

This section presents our approach to factual and counterfactual explanation generation for explaining predictions of an FRBCS and applies it to the use case introduced in Section II. We first introduce the concepts of fuzzy sets and linguistic variables that are essential for understanding the reasoning of an FRBCS. Second, the mechanism of linguistic interpretation is demonstrated for non-semantically grounded fuzzy linguistic terms. Third, a description of how explanations can be structured in natural language is offered. Fourth, all the previous notions are merged, as our methods for factual and counterfactual explanation generation for FRBCSs are described. Finally, we demonstrate how the end user can be involved in the process of explanation generation.

Essential fuzzy logic notions

The central notion of fuzzy logic is that of a fuzzy set. Unlike in binary Boolean logic where a variable can take on either of two values (i.e., true or false), fuzzy logic enhances estimation of any given prediction with a degree of certainty (e.g., "The leaf is likely to be of class Chinese horse chestnut"). The degree of certainty for each fuzzy set is determined by the value of the so-called membership function (MF), i.e., the function that maps the given numerical value from the input space (or the so-called universe of discourse) to the interval $[0, 1]$. The closer to 1, the more likely the given feature relates to the corresponding fuzzy set.

Numerical features of a test instance can be characterized in terms of fuzzy sets linked to a linguistic variable (e.g., Perimeter). Thus, all the values over which the feature is defined can be partitioned into several (e.g., triangular or trapezoidal) fuzzy sets in such a manner that it is always possible to measure the MF value for each fuzzy set that characterizes the given feature. In case of considering Strong Fuzzy Partitions [9], MF values for all fuzzy sets in the given universe of discourse are always said to sum to 1. Hence, if two fuzzy sets are found to overlap for the given feature value, they always provide complementary information with respect to the degree of certainty for that feature. Noteworthy, in this article, trapezoidal MFs are operated on in all cases.

The number of fuzzy sets and the corresponding linguistic terms can be set arbitrarily. An expert may categorize the given feature (e.g., Perimeter) to fall into either of two groups (e.g., small or large) or any of three (e.g., small, medium, large) or even more. It is then up to the expert which feature values should make up the regions corresponding to each linguistic term. If expert knowledge is unavailable, all feature values can be divided into an arbitrary number of equal-size buckets (i.e., a uniform partition), each of which is assigned to a predefined linguistic term.

Linguistic approximation

It was presupposed above that the linguistic terms assigned to fuzzy sets are linguistically meaningful. However, this may not necessarily be the case: some fuzzy classification algorithms (e.g., FURIA [10]) are trained to learn rules whose linguistic terms may not be semantically grounded. In this case, an extra-linguistic layer is necessary to be added to transform non-semantically grounded linguistic terms (e.g., Perimeter is MF0) into meaningful semantically-grounded linguistic terms (e.g., Perimeter is small). To do so, the mechanism of the so-called linguistic approximation is applied.

Despite having a well-formed prediction for any test instance, it is difficult to motivate it due to a lack of meaningful information encoded in the linguistic terms. Hence, it is necessary to apply linguistic approximation prior to generating a (factual or counterfactual) explanation. The linguistic meaning of a fuzzy set can be approximated in a series of the following steps:

  1. First, it is needed to reduce the dimensionality of the MF, i.e., a two-dimensional trapezoid is projected onto a one-dimensional line (also known as "alpha-cut") to subsequently be able to compare it to the known intervals of linguistic terms for the given feature. Note that the alpha-cut can be applied with an arbitrary value ranging from 0 to 1 for a given MF. It is nevertheless a common practice to set the value of alpha to 0.5. For trapezoidal MFs, this corresponds to finding the midline (or midsegment) of the trapezoid.
  2. Given the projection of the MF onto a line, one can inspect how similar it is to the intervals corresponding to all the linguistic terms for the given feature. To do so, a measure of interval similarity can be computed, e.g., the Jaccard similarity coefficient defined as follows: $$sim = \frac{a \cap b}{a \cup b}$$ where $sim \in [0, 1]$ is the similarity coefficient, $a$ and $b$ are the intervals being compared, respectively. In this case, $a$ is the MF's projection onto a line and $b$ is the interval of a linguistic term of the given feature.
  3. Once similarity coefficients are calculated for all the linguistic terms of the given feature, they can be ranked. The linguistic term having the highest similarity coefficient is assumed to most adequately approximate the MF linguistically and is therefore selected to replace the non-semantically grounded term in the rule. This procedure is repeated for all the features that the antecedent of the given rule contains.

For illustrative purposes, let us consider an arbitrary trapezoidal fuzzy set for characterizing Perimeter. Assume we define Perimeter to belong to any of the following five categories: Very small, Small, Medium, Large, or Very large (as in the default example for five fuzzy partitions from Fig. 3). These five categories exhaustively cover all possible perimeter values as they form a strong fuzzy partition.

Depending on the alpha-cut value applied to the trapezoidal MF, the term interval in this example will be approximated as either Small or Medium. Surface realization

Explanations are often best perceived when they are communicated in natural language. However, methods that generate explanations in natural language are still scarce [11]. As shown above, FRBCSs operate on conditional statements (i.e., IF-THEN rules) which can be transformed into natural language explanations and therefore serve as a communication interface between the classifier and the end user. Let us consider the typical structure of such explanations.

As we consider two types of explanations for the classifier's output in this article (factual and counterfactual), they can be framed in natural language as answers to why- and why-not-questions, respectively. Examples of such questions may, in general, include "Why is the given test instance of class P?" for requesting a factual explanation and "Why is the given test instance not of class Q, instead?" for requesting a counterfactual explanation. Typical answers to these questions could contain two clauses: main and subordinate. In case of factual explanations, the main clause would then claim the test instance to be of class P whereas the subordinate clause would indicate (possibly, several) causes for such an argument (e.g., "The leaf is Nanmu because area is not very small and perimeter is large"). As for counterfactual explanations, an explanation would present a conditional statement where the main clause (which is associated with the rule consequent) refers to a counterfactual class (e.g., "The leaf would be Crape myrtle ...") and the subordinate conditional clause (which is associated with the rule antecedent) would list the (most relevant) features to be minimally changed for the consequent to hold (e.g., "... if area were very small and perimeter were small").

Let us consider the linguistic structure of any general rule-based explanation. Following the examples above, one can single out three components that every main clause may have: the subject, the predicate (i.e., the verb), and an optional complement (e.g., a prepositional phrase). Thus, the test instance is said to always serve as the subject of the main clause while the verb (possibly, followed by an optional complement) communicates the action that the system claims to be the case. In the case of the subordinate clause, the subject may refer to the same test instance or a specific feature that characterizes it. In the former case, the verb may link the subject to a specific cause. In the latter case, the verb points to a (set of) value(-s) that the feature takes on.

Factual explanation generation

Previously, we introduced some of the core concepts underlying our explanation generation method (i.e., fuzzy sets and linguistic variables, linguistic approximation, and building blocks of natural language rule-based explanations). Based on this knowledge, the method for generating explanations for predictions of FRBCSs can now be introduced.

Let us start with the mechanism of factual explanation generation. Given the test instance $x$ that serves as input to an FRBCS, the classifier (i.e., the given FRBCS) is first run to obtain its prediction with respect to the given test instance. Then, we aim to factually explain why the given prediction is the case. As the internals of the FRBCS are accessible, its rule base can be inspected to collect all the rules that lead to the given predicted class. Then, the rules are ranked by their activation degree and the most activated one is selected to form the basis of the factual explanation. Subsequently, the linguistic terms of each feature from that rule are linguistically approximated if necessary.

Counterfactual explanation generation

As stated previously, classifier's predictions can be explained factually or counterfactually. The rule base can be counted on as a reliable mechanism to generate counterfactual explanations. In particular, the rules leading to counterfactual classes may enable us to reach the desired outcome [13].

Importantly, a counterfactual explanation is, by convention, supposed to represent the minimally different (set of) data point(-s) covered by the rule. This requirement to a counterfactual explanation is claimed to guarantee maximal relevance to the test instance under consideration. As there is typically more than one rule for each class, it becomes essential to design a strategy to find the most relevant counterfactual rule.

Taking into account the desideratum to explain the FRBCS reasoning applied to a specific test instance, one should look for the test instance-specific information that the FRBCS can provide us with. For this purpose, MF values for each feature-value pair (e.g., "Perimeter = MF0") can be retrieved from the FRBCS for the given prediction. Hence, it is possible to form a vector with all MF values that would describe the system's behavior with respect to the test instance (see Table 4).

Once all the rules of the counterfactual class are vectorized, their relevance to the test instance can be estimated. As both the test instance and the counterfactual rules are now represented as vectors, one can compute the distance between the test instance vector and each counterfactual rule vector. Whereas it is, in principle, possible to select any vector distance (or, alternatively, similarity) metric, it turns out the Euclidean distance best captures differences between the MF values and those present in counterfactual rule vector representations. The Euclidean distance is defined as follows: $$d(x, r_{cf}) = \sqrt{\sum\limits_{i} (x_i - r_i^{cf})^2} \in [0, \infty)$$ where $x$ is the test instance vector, $r^{cf}$ is a counterfactual rule vector, $x_i$ and $r_i^{cf}$ are the $i$-th elements in $x$ and $r^{cf}$, respectively.

Despite the fact that the resulting Euclidean distances between the test instance and each counterfactual rule are not normalized, they can still be used as an estimate of relevance of the counterfactual rules, as we are only interested in their ranking. Once they are ranked, it becomes possible to select the most relevant counterfactual rule (the one that has the lowest Euclidean distance to the test instance vector) for further processing.

If the linguistic terms of the features making part of the counterfactual rules are not semantically grounded, the selected rule undergoes the process of linguistic approximation. Finally, the most relevant (and, if necessary, linguistically approximated) counterfactual rule is passed on to the natural language generation module that transforms the rule into a well-formed natural language sentence.

User preferences and nearest neighborhood for counterfactual explanation generation

Although counterfactual explanations are known for their human-friendly nature and ability to aid in understanding machine learning models, they present several challenges. For example, counterfactual explanations usually lack user involvement, what hinders understanding. Therefore, it is crucial for users to provide feedback to define feasible ranges of counterfactual feature values, resulting in understandable and actionable explanations [14]. Accordingly, we have developed a counterfactual explanation approach that includes user feedback in the explanation generation process. By incorporating user feedback, automated explanations are more aligned with user expectations. Our approach utilizes feedback to personalize the explanations by providing acceptable ranges in the feature space where feasible counterfactuals can be found. The concept of neighborhood subspace that surrounds the test instance is an extended version of that proposed in the LIME method [15]. LIME utilizes local regression within the vicinity of the test instance to elucidate the rationale behind a model's prediction. This notion of the neighborhood subspace is leveraged; however, in our method, it is defined and adhered by user-preferred ranges to identify possible counterfactuals (i.e., perturbed instances). After finding the counterfactual instances, the distances between the original test instance and the counterfactual instances are computed to come up with counterfactual explanations.

In general, for the user-preferred approach, the user feedback is mainly divided into two parts: (i) a list of the features that the user selects to modify and (ii) feedback indicating the ranges of the selected features. As this approach handles mixed feature tabular datasets, the test instance may contain numerical and categorical features (in general). As a result, feedback about the numerical and categorical features is recorded separately. For numerical features, the user specifies a feasible range for the selected features, while for categorical features, feedback is recorded as to whether the feature value should be flipped with a value of $1$ or $0$ (binary categories). This approach focuses on feature-dependence and intrinsic aspects of counterfactual explanations. Accordingly, we look for an initial perturbation of features based on strong positive correlations, followed by an exhaustive search to identify counterfactual instances across all possible feature perturbation combinations guided by heuristics. For further details regarding heuristics, the interested readers are kindly referred to [16]. For each feature, uniform or marginal distribution-based synthetic data are generated within the predefined ranges (distribution depends on the features). In addition, to incorporate categorical features, they are kept the same or flipped as per user-preference.

Here, for illustrative purposes, the user feedback mechanism is simplified by providing a slider control to select the value ranges for Area and Perimeter (see Fig. 8). Both features are numerical. To discover the most suitable counterfactual explanation based on the smallest distance from the test instance assuring to provide desired outcome, an optimization algorithm proposed by Wachter et al. [17] is used and its loss function is presented mathematically as follows: $$L(m, x, x^{cf}, y') = (m(x^{cf}) - y')^2 + d(x^{cf}, x)$$ where $L$ is a loss function, $x$ is the test instance, $x^{cf}$ is a counterfactual instance, $y'$ is the desired outcome, $m$ is the machine learning model, and $d$ is the distance function. $L$ tries to minimize $d$ in such a way that the desired outcome $y'$ and the prediction of $m(x^{cf})$ are the same. The distance function $d(.,.)$ is customized as follows: $$d(x^{cf}, x) =\sum_{f=1}^{n}|x_f - x^{cf}_f|/MAD_f$$

The Manhattan distance weighted with median absolute deviation (MAD) is employed for each feature $f$ whereas $n$ is the total number of features (i.e., n=2 in our use case). MAD computes an absolute value which helps in sorting the counterfactuals.

Let us demonstrate how to generate a counterfactual explanation using the user-preferred (UP) approach for the test instance shown in Fig. 6. By adjusting the sliders for Area and Perimeter in Fig. 8, you can select a range of values for the counterfactual class you are looking for. Once you have made your selections, the table will show the corresponding counterfactual values for Area and Perimeter, along with a textual explanation using the linguistic terms introduced in Table 1. Additionally, the counterfactual explanation will be displayed as a blue point in Fig. 9, with the label "CF Class (UP)" denoting the best counterfactual generated with the user-preferred approach.

Notice that the previous interactive elements are cross-linked. Accordingly, the user-preferred approach will show a consistent behavior only if you explicitly selected previously the counterfactual class from the dropdown menu by clicking on the green button in Fig. 6, and in agreement with the counterfactual values of Area and Perimeter associated with Fig. 7. Similarly, you have to provide the feature ranges by moving the sliders of Area and Perimeter in Fig. 8 to see the best found counterfactual point plotted in Fig. 9 colored blue and labeled "CF class (UP)".

IV. Discussion and concluding remarks

Fuzzy sets and systems are well known because of their ability to deal with approximate reasoning, mainly in control applications. Even though great effort has been made in the research community to establish the basis for ensuring interpretability of fuzzy systems, more work is still required for ensuring explainability. In this work, we have sketched how to make fuzzy classifiers not only interpretable by careful design but also explainable. Explainable Fuzzy Systems can provide users with both factual and counterfactual explanations in natural language.

In the previous sections, several interactive components were presented with the aim of illustrating two complementary approaches to factual and counterfactual explanation generation that can be applied to distinct classifiers. The presented explanation generation algorithms differ in nature and output representation. On the one hand, the fuzzy logic-based explanation generation method is model-specific, i.e., it operates on the internals of the given FRBCS and primarily aims to explain the output of the FRBCS itself. On the other hand, the described feedback-based counterfactual explanation generation method is model-agnostic, i.e., it does not require access to the internals of the model and inspects the data region around the test instance in the search of a minimally different potential counterfactual data point. Notwithstanding the foregoing, the fuzzy logic-based method can be used as part of a model-agnostic explanation generation method if the FRBCS under consideration is, e.g., trained on a local neighborhood around the test instance. In this regard, both methods may as well be applied to explain the output of other classifiers.

As for the output representation, both methods produce textual explanations. However, the fuzzy logic-based method generates explanations that cover a set of counterfactual points whereas the feedback-based algorithm generates a single data point and forms the explanation based on the features of that data point.

The presented methods have some limitations. As stated previously, the explanation generation method for FRBCSs is model-specific. Therefore, its applicability is limited to the family of interpretable rule-based classifiers whose internals are available and can be transformed into rules (if necessary). In addition, the feature space is assumed to always be known and interpretable. As for the user preference-based method, overly restrictive user feedback can lead to sub-optimal solutions to the optimization problem when generating counterfactuals.

Importantly, the end user is assumed to understand the generated explanations. However, the understandability of the explanations can be undermined if the user has little domain knowledge (if any). Whereas the user preference-based method allows the end user to fine-tune the initially generated explanation, it does not enable him or her to learn facts about the application domain. In this regard, the social aspect of explanation can be enhanced if the user is engaged in an explanatory dialogue with the explainer [18]. Interacting with the system via dialogue, the user can gain further domain knowledge and, if found necessary, inspect explanations alternative to those offered initially.

It is worth noting that the development of Explainable and Trustworthy AI has made fuzzy sets and systems regain attention. Thus, model-specific methods have, e.g., been applied to address causality in the context of counterfactual explanation generation for fuzzy rule-based classification systems [19]. Alternative methods have been used for generating factual and counterfactual explanations for fuzzy classification trees [20], [21]. All in all, these fuzzy-based approaches deal naturally with imprecision and uncertainty in the generation of explanations. Moreover, the ability to produce natural linguistic explanations is what makes special the approach presented in this work, which highlights the relevance of explainable fuzzy systems [4]. For an overview of factual and counterfactual explanation generation algorithms (including those targeting other supervised machine learning classifiers), the interested readers are kindly referred to recent surveys, e.g., [22] or [23].

The work presented in this immersive article points to several lines of future work. First, further experiments with other classifiers are required to ensure the generalizability of the described algorithms. In addition, these methods may have to be improved to incorporate such properties of counterfactuals as causality, actionability, or discriminative power. Third, the impact of alternative explanations on the end user needs to be investigated further, as user-preferred explanations can differ (sometimes, largely) from the initially offered ones.

In conclusion, the presented methods for factual and counterfactual textual explanation generation provide complementary means for explaining classification systems. As they employ different strategies for explanation generation and differ in output representation, they can be used complementarily to each other. The choice of the algorithm to use may depend on the available domain knowledge, target audience, or specific properties of explanations favored in the given settings.
